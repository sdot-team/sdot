Performance ​

This page gives the measured cost of sdot: a single power diagram, a whole Newton solve, CPU against GPU, and how both scale with the number of diracs and with the dimension. Every number comes from the scripts in bench/. The Reproducing section gives the commands.

Setup ​

machinehardwareused for
lmoXeon W-2145 (8 cores, 8 pinned threads), RTX 2080 Ti (Turing, FP64 at 1/32)CPU, 2D GPU
n22RTX A6000 (Ampere, 48 GB, FP64 at 1/64)3D GPU, 2D GPU at 1e6

Protocol:

  • A Newton solve starts cold, from the Voronoi diagram (zero weights), tree build included. It stops when max |mass - target| / target <= 1e-6.
  • GPU times are for a jitted call (JAX). An eager call costs about 0.1 s more.
  • mixed (the GPU default) runs the float kernel and switches to the double kernel when float precision is no longer enough. The final accuracy is the double one.

One power diagram ​

This is the cost of computing every cell's measure for fixed weights. It is the inner loop of every solver, measured in nanoseconds per dirac (kernel time only).

So a 2D diagram with one million diracs takes about 10 ms on a gaming GPU, and a 3D one about 120 ms.

In float, the cell measures match the double kernel to a median relative error of 1e-14 in 2D (max 1e-8). In 3D the median error is 0 and the maximum 7e-5. The mixed mode then finishes the solve in double.

Scaling with the number of diracs ​

The number of Newton iterations barely depends on n (5 iterations and 6 diagrams for a uniform cloud at 1e5 and 1e6). The total cost therefore follows the cost of one diagram plus one linear solve, which are both close to linear in n.

At 1e7 diracs in 3D, the float kernel can no longer resolve the cells (each cell is about 4.6e-3 wide in a unit box), so the solve switches to the double kernel. On cards with slow FP64 this switch costs half of the total time.

GPU memory is about 900 bytes per dirac in 2D and 1300 in 3D at 1e6. A solve that does not fit raises a MemoryError before it starts.

Newton is not affected by the dimension: the iteration count (5 iterations, 6 diagrams) and the cost of the linear solves (under 2.5 s at 1e5) stay the same up to 6D. The whole cost is in the cells. A Laguerre cell of a uniform cloud has a number of vertices that grows very fast with d (the last column, averaged over a few thousand diracs), and the cell is cut, measured and triangulated vertex by vertex. Each added dimension multiplies the cost of a diagram by about 20 (3D to 4D, 4D to 5D), then by about 40 from 5D to 6D.

In practice, 4D is comfortable up to a few 10⁵ diracs and 5D up to about 10⁵. 6D is limited to about 10⁴ diracs (an hour on 8 cores). Beyond that, the cost comes from the geometry of the cells, not from the solver.
