Projected Sources ​

A cloud of points xi of Rd, seen along a batch of directions: for each unit vector na, the 1D measure

μa=1n∑ifi(⋅−xi⋅na)

on the line, where fi is the profile a point leaves there. μa is transported to a 1D target νa, one per direction, and the cost is W22(μa,νa), differentiable with respect to the points. It is the right tool wherever the data are 1D marginals of a cloud: the projections of an object in tomography, for example.

The cost is the same as for any other source, only the source is never built: with 107 points and 103 directions the [ directions, n ] array of the projected positions is 80 GB. The classes below compute xi⋅na on the fly, in the kernels, and scatter the gradients back onto the shared points.

Classfi
ProjectedSumOfDiracs( points, normal )a dirac at xi⋅n
ProjectedSumOfTents( points, half_widths, normal )(1−|s|/wi)+/wi, a tent of half-width wicontinuous
ProjectedSumOfAnisotropicTents( points, matrices, normal )the same, with the half-width wi=|MiTn| that depends on the directionthe shadow of an ellipse

points [ n, d ], half_widths [ n ] and the masses are shared by all the directions. normal has one row per direction, declared as a batch axis, and so does the target: a 1D Image, one profile per direction.

Diracs ​

python
from loom.tensor import Axis, ShapeVar

num_angle = Axis( ShapeVar( len( normals ) ), name = "num_angle" )           # the batch: one transport per direction
src = sdot.ProjectedSumOfDiracs( points = x, normal = normals, batch_axes = [ num_angle ] )
dst = sdot.Image( values = profiles, origin = [ s_min ], pixel_frame = [ [ dw ] ], batch_axes = [ num_angle ] )

plan = sdot.SdotPlan1d( src, dst )
plan.cost                                        # [ directions ]: W2^2 per direction, both sides normalized to mass 1

normals is [ directions, d ], profiles [ directions, bins ]: the mean density on the bins of width dw from s_min. In 1D the plan is a sort, exact, and jax.grad of plan.cost.sum() with respect to x is what you expect.

The cost is only piecewise smooth, though: when two diracs cross on the line they exchange their ranks, and the gradient jumps. A descent on the positions of many diracs, whose projections cross all the time, feels it.

Tents ​

A tent is the simplest object with a width. Two tents that cross just overlap, and the cost stays smooth.

python
src = sdot.ProjectedSumOfTents( points = x, half_widths = w, normal = normals, batch_axes = [ num_angle ] )
plan = sdot.ContinuousOtPlan1d( src, dst )
plan.cost

ContinuousOtPlan1d is the transport between two continuous densities on a line, here piecewise linear against piecewise constant. It is exact: per direction the 3n breakpoints of the tents are sorted, and on each piece the transport map is quadratic, integrated by a 3-point Gauss-Legendre rule. It differentiates with respect to both points and half_widths:

python
def cost( x, w ):
    src = sdot.ProjectedSumOfTents( points = x, half_widths = w, normal = normals, batch_axes = [ num_angle ] )
    return sdot.ContinuousOtPlan1d( src, dst ).cost.sum()

grad_x, grad_w = jax.grad( cost, argnums = ( 0, 1 ) )( x, w )

Options of ContinuousOtPlan1d:

  • with_barycenters = True: the barycenter of the transport of each tent ( plan.barycenters );
  • with_gradient = True: the gradient of plan.cost.sum() comes out of the same pass ( plan.points_grad, plan.half_widths_grad ), half the work of jax.value_and_grad, whose adjoint runs the transport again. The call is then not differentiated: it goes inside a jax.custom_vjp that returns these gradients. Optional: jax.grad of the plain cost works as is ( see Tomography with tents ), and this is about twice as fast with many tents;
  • method = "grid", scale = 8: each tent taken as uniform inside the cells of a grid scale times finer than the bins of the target: an exact deposit of the tents into the cells, then a transport with no sort at all, in O(n×cells per tent) per direction. The error vanishes as scale grows. This is the version for a card and many tents ( the target's bins must be uniform ).

Anisotropic tents ​

A round object projects to the same tent at every direction. An ellipse does not: the image of a disk by a matrix Mi has, along the direction n, a shadow of half-width wi(n)=|MiTn| ( the support function of the ellipse ). ProjectedSumOfAnisotropicTents( points, matrices, normal ) is the tent of that half-width, with matrices [ n, d, d ]; round tents are matrices = w * identity.

python
src = sdot.ProjectedSumOfAnisotropicTents( points = x, matrices = M, normal = normals, batch_axes = [ num_angle ] )
plan = sdot.ContinuousOtPlan1d( src, dst )

It is differentiated with respect to points and matrices ( jax.grad of plan.cost.sum() ), in the exact and in the grid methods. Not yet: with_gradient, and the card ( its kernels read the half-widths from the first direction, and refuse this type at compile time ). matrices must keep |MiTn|>0 at every direction; M = L L^T + \varepsilon I with L free is a parametrization that does. Keep ProjectedSumOfTents for round tents: it computes one half-width per tent where this class computes one per tent and direction, and it has the one-pass gradient and the card.

Domes: the projection of a radial density ​

An object that has a size in the plane projects to the same profile at every direction, if it is radial. The density (1−|x|2/r2)+k−1/2 gives, by Abel transform, ck(1−s2/r2)+k. For k=1 it is the closest thing to a disk ( the disk itself would be k=1/2, whose profile has a vertical tangent at the edge ). A dome is such an object: its profile has a closed-form primitive, so its exact mass in each cell of a fine grid is known. sdot.projected1d.ProjectedLoss1d computes the loss for domes ( or tents ) in three steps, none of which sorts or builds an [ directions, n ] array:

  1. deposit: each object puts into every fine cell it covers its exact mass, from the primitive of f;
  2. grid transport, per direction: W22 between two densities piecewise constant on the same grid, exact, in O(directions×cells);
  3. gather: ∂L/∂xi from the same primitives.
python
from sdot.projected1d import ProjectedLoss1d

L = ProjectedLoss1d( angles, profiles, s_min, dw, shape = "dome", k = 1, max_radius = 0.05 )
value = L( points, radii )                          # differentiable in points [ n, 2 ] and radii [ n ]

angles are in the plane ( normals (cos,sin) ). The only approximation is the grid ( scale fine cells per bin, 8 by default ); fused kernels, CPU and CUDA, run steps 1 and 3, and backend = "jax" is the reference. L.sharded( mesh ) splits the directions between the devices of a jax.sharding.Mesh, and a batch axis solves K problems of the same geometry at once. On a 2080 Ti, one value and gradient takes 615 ms for 107 objects, 600 directions and 2048 bins.

Optimizing the positions ​

The cost is a plain jax function of the points, so any optimizer does. sdot.device_optim.lbfgs( value_and_grad, x0 ) is an L-BFGS whose loop is one compiled lax.while_loop, with no round trip to the host between the steps; it returns ( x, info ), info[ "losses" ] holding the loss after each step, and can call back every few steps ( snapshot_every, on_snapshot ) to watch the descent. gradient_descent is its plain counterpart. A multiscale use: Tomography with tents.
