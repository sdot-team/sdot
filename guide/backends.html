Frameworks and Devices ​

sdot works with NumPy, JAX, PyTorch and CuPy arrays. There is nothing to configure: the inputs decide. A transport computed from JAX arrays runs where they live and returns JAX arrays, one computed from PyTorch tensors returns PyTorch tensors, and so on:

py
import numpy as np
import sdot

rng = np.random.default_rng( 0 )
f = sdot.SumOfDiracs( rng.random( ( 100, 2 ) ) )  # 100 diracs of equal mass
g = sdot.Image( rng.random( ( 10, 10 ) ) )  # a 10 x 10 image, on the unit square

print( sdot.w2( f, g ) )  # W2^2, as a numpy array
py
import jax
import sdot

k1, k2 = jax.random.split( jax.random.key( 0 ) )
f = sdot.SumOfDiracs( jax.random.uniform( k1, ( 100, 2 ) ) )  # 100 diracs of equal mass
g = sdot.Image( jax.random.uniform( k2, ( 10, 10 ) ) )  # a 10 x 10 image, on the unit square

print( sdot.w2( f, g ) )  # W2^2, as a jax array
py
import torch
import sdot

f = sdot.SumOfDiracs( torch.rand( 100, 2 ) )  # 100 diracs of equal mass
g = sdot.Image( torch.rand( 10, 10 ) )  # a 10 x 10 image, on the unit square

print( sdot.w2( f, g ) )  # W2^2, as a torch tensor
py
import cupy as cp
import sdot

rng = cp.random.default_rng( 0 )
f = sdot.SumOfDiracs( rng.random( ( 100, 2 ) ) )  # 100 diracs of equal mass
g = sdot.Image( rng.random( ( 10, 10 ) ) )  # a 10 x 10 image, on the unit square

print( sdot.w2( f, g ) )  # W2^2, as a cupy array, computed on the GPU
  • Objects: a plan, a distribution... hand back arrays of the same framework: p.barycenters is a JAX array when the inputs were JAX arrays.
  • Devices: the computation runs on the device of the inputs. On a CUDA GPU, the whole solve runs on the card for 2D problems ( against a box, a polygon, an image, gaussians or a triangle mesh ) and for 3D problems against a uniform density, isotropic gaussians or a tetrahedral mesh; anything else raises there.
  • Gradients: jax.grad and torch.autograd go through w2 and the outputs of a plan, with respect to the diracs and to the parameters of the target ( an image's values, frame and origin, gaussians, a mesh's values... ), on the CPU and on a CUDA GPU, under jax.jit and for batches of cotangents ( jax.jacrev ). In 1D, the barycenters derive when the plan stores them ( Direct( with_barycenters = True ) ).
  • jax.jit: the whole solve is one call inside the compiled program.
  • Precision: JAX works in float32 unless jax_enable_x64 is set; float64 is recommended for gradients.

What decides, when nothing does ​

A value built from nothing ( a list, a number ) takes the default framework: the one already imported, or loom.default_framework. sdot relies on loom for this; see its page on frameworks and devices.

Compiled kernels ​

The C++ / CUDA kernels come precompiled with the package for the common cases. Another combination ( a dimension, a distribution, a device ) is compiled on first use and cached, which needs a C++ compiler ( and nvcc for NVIDIA GPUs ).
